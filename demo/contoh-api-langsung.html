❓ Kenapa URL mentah "tidak bisa" dibuka di browser?

Apps Script web app selalu mengembalikan redirect 302 ke script.googleusercontent.com sebelum JSON-nya ditampilkan. Saat kamu mengetik …/exec?action=generateReport langsung di address bar, browser biasanya tetap bisa menampilkan JSON setelah redirect — tapi beberapa browser/konteks (mis. <a href> tanpa target, atau tool yang tidak mengikuti redirect) hanya menunjukkan halaman kosong atau URL redirect panjang.

Solusi andal: panggil lewat fetch(..., {redirect: "follow"}) dari JavaScript. CORS sudah dibuka (Access-Control-Allow-Origin: *), jadi halaman mana pun bisa memanggilnya:

const API = "https://script.google.com/macros/s/AKfycbzZtRJ8dDEj6y3VyQgbYRap1-BBkOrOb-5vapHI7ck2ki751kqwudADvm8YSfEkzkRB/exec";

async function panggil(params) {
  const qs = new URLSearchParams(params).toString();
  const res = await fetch(`${API}?${qs}`, { method: "GET", redirect: "follow", mode: "cors" });
  const teks = await res.text();
  return JSON.parse(teks); // backend selalu JSON
}

🔄 Cara kirim sebagai user lain — otomatis terkirim

Hasil kuis/aktivitas otomatis terkirim ke backend lewat dua jalur:

  1. Komponen memancarkan event dasbor-kuis-log; host <dasbor-kuis> menangkapnya, membuat id_log unik (atau memakai yang dikirim komponen), lalu menaruh log ke antrean lokal a3_v5_sync_queue.
  2. Antrean di-flush otomatis ke action=logActivity saat online, jendela difokuskan, atau halaman dimuat ulang. Backend menolak id_log duplikat (idempotensi v5.1), jadi tidak ada baris rangkap.

Beda user = beda sesi. Komponen membaca studentId dari localStorage (quiz_user_session, TTL 24 jam) yang diisi <quiz-user-auth> saat login. Untuk berpindah user: logout (hapus sesi) lalu login dengan NIS/email lain — semua kiriman berikutnya otomatis memakai studentId sesi baru. Bila ingin memaksa, set atribut student-id / student-name dsb. pada <kuis-ledakan>.

Contoh nyata di sheet db_nilai: baris Test Cek Kuis | 77 | formatif | LOG-CHECK-584205 dan Test Unik | 71 | formatif | LOG-609385 adalah hasil kuis yang dikirim lewat jalur di atas — skor ditulis ke db_nilai (kategori formatif) oleh logActivity, lalu tampil di Rangkuman setelah generateReport.
