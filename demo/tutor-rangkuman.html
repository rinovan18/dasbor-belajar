📚 Tutor: Rangkuman

Cara kerja sheet Rangkuman — satu baris per siswa untuk leaderboard guru, dihasilkan generateReport dari db_nilai + db_aktivitas di lib/codev5.gs.

← Demo utama (index.html) 🗂 Hubungan Sheet 📊 Tutor Akumulasi Nilai Rapor 🔎 Hasil Cek Perubahan

🔄 Alur Data — hingga menjadi Rangkuman

1
Siswa mengerjakan kuis / beraktivitas. <kuis-ledakan>, <ruang-diskusi>, <kirim-tugas>, <sistem-kehadiran>, atau <dasbor-kuis> mengirim action=logActivity (GET, ramah CORS) lengkap dengan id_log unik.
2
Backend menulis data mentah. Tiap aktivitas masuk db_aktivitas; bila tipenya quiz, skor juga ditulis ke db_nilai (kategori: formatif, ulangan_harian, uts, uas, sumatif). Anti double-entry via id_log + fingerprint + LockService.
3
Guru memanggil action=generateReport. Backend membaca db_nilai, db_aktivitas, Users, db_kehadiran lalu menimpa sheet Rangkuman (dan Akumulasi Nilai Rapor).
4
Frontend memuat action=getLeaderboard. Membaca Rangkuman dan mengurutkan berdasarkan Rata-rata Skor tertinggi (opsional filter kelas).
Kuis tidak wajib menunggu generateReport. getScores dan getStudentRoster tetap membaca db_nilai / sheet rapor yang sudah ada. generateReport hanya memadatkan ulang agar Rangkuman & Rapor selalu sinkron.

🛡 Anti double-entry: tiap aktivitas membawa id_log. Backend men-serial-kan tulis dengan LockService, menolak id_log yang sudah tercatat, memangkas baris rangkap, dan menolak baris identik (fingerprint Tanggal+Tipe+Deskripsi+Kode Materi+Student ID). dedupTransaksi membersihkan data lama bila perlu.

🚀 Cara Menjalankan

1. Salin seluruh isi lib/codev5.gs ke editor Apps Script spreadsheet kamu → Deploy → Web app (execute as Me, akses Anyone).

2. Tempel URL /exec ke atribut apps-script-url pada komponen / demo (lihat DATA-CONTOH.md).

3. Panggil ?action=generateReport agar Rangkuman terisi, lalu lihat leaderboard di Mode Guru.

4. Bila ada baris rangkap dari versi lama: panggil ?action=dedupTransaksi, lalu generateReport lagi.
